# Named enum types that more than one migration site can create. This is
# migration debt, not permission: PostgreSQL rejects a second CREATE TYPE, and
# the fresh-database CI path cannot see it, because 001 builds the schema from
# model metadata and _safe_create_table then skips the tables whose creation
# would emit it. Only an incremental database reaches the failure.
# Counts must only shrink; new entries require an explicit owner and review.
# Format: enum-type-name count repository-relative-path.
#
# EMPTY BY REPAIR, NOT BY EXEMPTION. This file was enrolled with 25 entries
# across migrations 430-434 when the guard landed (#1662); the repair (#1661)
# gave every one of those enums a single creator, so the detector now reports
# zero duplicates and the baseline shrank to nothing. Keep the file: it is the
# ratchet. An empty baseline means the next duplicate creator fails CI outright
# instead of being quietly absorbed.
